WHAT TO BUILD:

1. lib/paystack/client.ts — a small typed client using `fetch` only, no new dependencies:
   - PAYSTACK_BASE = 'https://api.paystack.co'
   - reads PAYSTACK_SECRET_KEY from process.env; if absent, every function throws a clear
     "PAYSTACK_SECRET_KEY is not set" error (do not fall back to a mock and do not invent a success)
   - initializeTransaction({ email, amountKobo, planCode?, reference, callbackUrl, metadata })
     -> POST /transaction/initialize, returns { authorizationUrl, reference, accessCode }
   - verifyTransaction(reference) -> GET /transaction/verify/:reference
   - verifyWebhookSignature(rawBody: string, signatureHeader: string | null): boolean
     -> HMAC-SHA512 of the raw request body using PAYSTACK_SECRET_KEY, compared to the header with a
        timing-safe compare (crypto.timingSafeEqual). This is the security boundary of the whole feature.
   - Amounts are in the smallest unit (cents/kobo): R299 -> 29900. Export one helper toKobo(rand).

2. app/api/paystack/checkout/route.ts — POST
   - Require a session via auth.api.getSession({ headers: request.headers }); 401 if absent.
   - Body { tier: 'pro' | 'business' }; validate and reject anything else with 400.
   - Plan codes from env: PAYSTACK_PLAN_PRO, PAYSTACK_PLAN_BUSINESS. If the requested plan's code is
     missing, return 503 with a message naming the missing variable.
   - Build a unique reference, pass the user id and tier in metadata, and return the authorization URL.
   - Never return the secret key or any part of it.

3. app/api/webhooks/paystack/route.ts — POST
   - Read the RAW body text BEFORE parsing JSON, verify the x-paystack-signature header with the function
     above, and return 401 immediately if it does not verify. No database write may happen before this.
   - Handle events idempotently. Paystack retries webhooks, so the same event must never credit twice.
     Use an existing events/webhook table if the schema has one; if it does not, make idempotency work
     with what exists (for example a unique reference recorded on the user or a dedicated table you
     create via the drizzle schema) and explain your choice in the report.
   - Handle `charge.success` (one-off credit purchase): credit the user's `credits` from metadata.
   - Handle `subscription.create` (and `invoice.payment_succeeded` if present): set the user's `tier`
     from the plan code and top up the tier's credits. Tier sizes already used by this app: pro = 500
     credits, business = 2000 credits.
   - Handle `subscription.disable` / `subscription.not_renew`: drop the user back to tier 'free'.
   - Always return 200 quickly for events you accept; return 200 for events you deliberately ignore
     (unknown event types) so Paystack does not retry them forever, and log what you ignored.
   - Log through the shared logger (lib/logger), never with console.log, and never log the secret key or
     a full signature.
