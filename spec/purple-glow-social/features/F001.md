## Overview

### Problem Statement

Currently, Purple Glow Social 2.0 has a gap in the post creation workflow:

1. **No Draft Saving**: Users can generate AI content but cannot save it as a draft for later editing
2. **No Post Editing**: Once content is generated, users cannot edit it before publishing
3. **No Draft-to-Schedule Flow**: The "Schedule Post" button in AI Content Studio is non-functional
4. **No Unified Post Creation**: Post creation is fragmented between AI generation and scheduling
5. **No Image Upload UI**: While the backend supports images, there's no user-facing upload interface

The database schema already supports `draft` status (line 4 in schema.ts: `statusEnum`), but the functionality is not implemented in the UI or API.

### Solution Summary

Implement a complete post creation workflow that allows users to:
- Create posts manually or from AI-generated content
- Save posts as drafts
- Edit drafts with a rich editing experience
- Upload and manage images for posts
- Convert drafts to scheduled or immediately published posts
- Manage all drafts from a dedicated view

### User Stories

**US-001: As a** small business owner  
**I want** to save AI-generated content as a draft  
**So that** I can review and edit it before publishing

**US-002: As a** social media manager  
**I want** to create posts manually without AI  
**So that** I have full control over my content

**US-003: As a** user  
**I want** to edit my drafts  
**So that** I can perfect my content before it goes live

**US-004: As a** user  
**I want** to upload images to my posts  
**So that** my content is more engaging

**US-005: As a** user  
**I want** to see all my drafts in one place  
**So that** I can manage my content pipeline efficiently

**US-006: As a** user  
**I want** to convert a draft to a scheduled post  
**So that** I can plan my content calendar

### Success Criteria

- [ ] Users can save AI-generated content as drafts with one click
- [ ] Users can create new posts manually (without AI)
- [ ] Users can edit any draft post (content, platform, topic)
- [ ] Users can upload images via drag-and-drop or file picker
- [ ] Users can view all drafts in a dedicated "Drafts" tab/view
- [ ] Users can delete drafts
- [ ] Users can convert drafts to scheduled posts via the schedule modal
- [ ] Users can publish drafts immediately
- [ ] Draft count is visible in the dashboard
- [ ] All operations work on mobile devices

## Requirements

### Functional Requirements

#### FR-001: Create Draft from AI Content
**Priority:** Must Have  
**Description:** When a user generates AI content, they can save any variation as a draft with a single click.

**Acceptance Criteria:**
- [ ] "Save as Draft" button appears for each AI-generated variation
- [ ] Clicking saves the content, platform, tone, and topic to the database
- [ ] User receives visual feedback (toast notification) on successful save
- [ ] Draft is immediately accessible in the drafts view
- [ ] Hashtags are preserved with the draft

#### FR-002: Create Draft Manually
**Priority:** Must Have  
**Description:** Users can create a new post from scratch without using AI generation.

**Acceptance Criteria:**
- [ ] "New Post" or "Create Draft" button in dashboard/schedule view
- [ ] Opens a post creation modal/form
- [ ] User can select platform, enter content, add topic
- [ ] User can save as draft or proceed to schedule/publish
- [ ] Character count displayed based on selected platform

#### FR-003: Edit Draft
**Priority:** Must Have  
**Description:** Users can modify any saved draft before publishing.

**Acceptance Criteria:**
- [ ] Edit button on each draft in the drafts list
- [ ] Opens edit modal with pre-filled content
- [ ] User can modify: content, platform, topic, image
- [ ] Changes are saved to the database
- [ ] Last modified timestamp is updated

#### FR-004: Image Upload
**Priority:** Must Have  
**Description:** Users can upload images to attach to their posts.

**Acceptance Criteria:**
- [ ] Drag-and-drop zone for image upload
- [ ] File picker as alternative
- [ ] Image preview before saving
- [ ] Support for JPEG, PNG, WebP formats
- [ ] Max file size: 5MB
- [ ] Images stored via Vercel Blob
- [ ] Image can be removed/replaced

#### FR-005: Drafts List View
**Priority:** Must Have  
**Description:** Dedicated view showing all user drafts.

**Acceptance Criteria:**
- [ ] Accessible from dashboard navigation
- [ ] Shows draft content preview (truncated)
- [ ] Shows platform icon
- [ ] Shows creation date
- [ ] Shows last modified date
- [ ] Supports sorting (newest, oldest, platform)
- [ ] Supports filtering by platform
- [ ] Pagination for large draft counts

#### FR-006: Delete Draft
**Priority:** Must Have  
**Description:** Users can permanently delete drafts they no longer need.

**Acceptance Criteria:**
- [ ] Delete button on each draft
- [ ] Confirmation dialog before deletion
- [ ] Draft removed from database
- [ ] Associated image deleted from Vercel Blob
- [ ] Toast notification on success

#### FR-007: Convert Draft to Scheduled Post
**Priority:** Must Have  
**Description:** Users can schedule a draft for future publication.

**Acceptance Criteria:**
- [ ] "Schedule" button on each draft
- [ ] Opens schedule modal with draft content pre-loaded
- [ ] User selects date/time
- [ ] Draft status changes to "scheduled"
- [ ] Credit reservation created
- [ ] Post appears in schedule view

#### FR-008: Publish Draft Immediately
**Priority:** Should Have  
**Description:** Users can publish a draft immediately without scheduling.

**Acceptance Criteria:**
- [ ] "Publish Now" button on each draft
- [ ] Confirmation dialog with credit cost
- [ ] Uses existing publish API
- [ ] Draft status changes to "posted"
- [ ] Success/failure feedback provided

#### FR-009: Draft Statistics
**Priority:** Should Have  
**Description:** Dashboard shows draft-related statistics.

**Acceptance Criteria:**
- [ ] Draft count visible in dashboard stats
- [ ] Draft count included in post stats API response
- [ ] Visual indicator when drafts exist

#### FR-010: Multi-Platform Draft
**Priority:** Nice to Have  
**Description:** A single draft can be configured for multiple platforms.

**Acceptance Criteria:**
- [ ] Platform selection allows multiple choices
- [ ] Content adapts to each platform's limits
- [ ] Preview shows platform-specific versions
- [ ] Scheduling creates separate posts per platform

### Non-Functional Requirements

#### NFR-001: Performance
- Draft save operation: < 500ms response time
- Draft list load: < 1s for up to 100 drafts
- Image upload: < 3s for 5MB file
- Support 200 concurrent draft operations

#### NFR-002: Security
- All draft operations require authentication
- Users can only access their own drafts
- Image uploads validated for type and size server-side
- CSRF protection on all mutations
- Rate limiting: 30 draft operations per minute

#### NFR-003: Reliability
- Draft auto-save every 30 seconds during editing (optional enhancement)
- Graceful handling of network failures
- Optimistic UI updates with rollback on failure

#### NFR-004: Usability
- Mobile-responsive design (320px minimum)
- Keyboard accessible (Tab navigation, Enter to submit)
- Clear visual feedback for all operations
- Character count with platform-specific limits
- Accessible to screen readers (WCAG AA)

#### NFR-005: Data Integrity
- Drafts persist across sessions
- Images remain linked to drafts until explicitly deleted
- Deleted drafts trigger image cleanup

### Data Models

#### Database Schema (Existing - No Changes Required)

The `posts` table already supports drafts via the `status` field:

```typescript
// drizzle/schema.ts - EXISTING (no changes needed)
export const statusEnum = pgEnum("status", ["draft", "scheduled", "posted", "failed"]);

export const posts = pgTable("posts", {
  id: uuid("id").defaultRandom().primaryKey(),
  userId: text("user_id").notNull().references(() => user.id),
  content: text("content").notNull(),
  imageUrl: text("image_url"),           // Already supports images
  videoUrl: text("video_url"),
  platform: platformEnum("platform").notNull(),
  status: statusEnum("status").default("draft"),  // Default is draft!
  topic: text("topic"),
  scheduledDate: timestamp("scheduled_date"),
  platformPostId: text("platform_post_id"),
  platformPostUrl: text("platform_post_url"),
  publishedAt: timestamp("published_at"),
  errorMessage: text("error_message"),
  createdAt: timestamp("created_at").defaultNow(),
  updatedAt: timestamp("updated_at").defaultNow(),
});
```

## Security Considerations

### Authentication & Authorization
- All draft endpoints require valid session via Better-auth
- Users can only CRUD their own drafts (userId check in all queries)
- Admin users cannot bypass user draft ownership (no admin override)

### Data Protection
- Draft content is stored in PostgreSQL (encrypted at rest via Neon)
- Images stored in Vercel Blob (encrypted at rest)
- No sensitive data in draft content (user responsibility)

### Input Validation
- Content length validated (max 10,000 characters)
- Platform must be valid enum value
- Image URLs must be valid Vercel Blob URLs
- Topic limited to 200 characters
- All inputs sanitized before database insert

### Rate Limiting
- Draft CRUD: 30 requests per minute per user
- Image upload: 10 requests per minute per user
- Prevents spam and resource exhaustion

### Audit Logging
- Log draft creation with userId and platform
- Log draft deletion with userId and draftId
- Log image uploads with userId and file size
- All logs sanitized (no content in logs)

---

## Performance Considerations

### Optimization Strategies
- Paginate draft lists (max 100 per request)
- Lazy load images in draft cards
- Debounce auto-save during editing (if implemented)
- Use optimistic UI updates for better perceived performance

### Caching
- No server-side caching for drafts (always fresh)
- Client-side: SWR or React Query for draft list (optional enhancement)
- Image URLs cached by browser (Vercel Blob headers)

### Database Queries
- Index on `posts.userId` and `posts.status` (already exists)
- Combined index for `(userId, status)` queries recommended
- Limit default page size to 20 to reduce payload

### Image Handling
- Vercel Blob handles CDN distribution
- Images resized on client before upload (optional enhancement)
- Max 5MB to prevent long upload times

## Rollout Plan

### Deployment Strategy

2. Existing drafts remain in database but inaccessible via UI

## Known Limitations

1. **Single Platform per Draft**: Initial release supports one platform per draft. Multi-platform drafts deferred to future enhancement.

2. **No Auto-Save**: Drafts are saved only on explicit user action. Auto-save during editing may be added in future release.

3. **No Version History**: Editing a draft overwrites previous content. No undo or version history.

4. **Image Size Limit**: 5MB max per image. Larger images must be compressed before upload.

5. **No Video Support**: Video uploads not supported in this release. Uses existing `videoUrl` field but no upload UI.

6. **No Bulk Operations**: Cannot select multiple drafts for bulk delete/schedule. Future enhancement.

---

## Future Enhancements

1. **Auto-Save**: Automatically save draft content every 30 seconds during editing
2. **Version History**: Track changes to drafts with ability to revert
3. **Multi-Platform Drafts**: Single draft targeting multiple platforms with content adaptation
4. **Bulk Operations**: Select multiple drafts for bulk actions
5. **Draft Templates**: Save commonly used draft structures as templates
6. **Draft Sharing**: Share draft preview link for approval workflows
7. **Video Upload**: Support video content in drafts
8. **AI Enhancement**: Button to "Improve this draft" with AI suggestions
9. **Draft Expiry**: Automatic cleanup of old unused drafts
10. **Draft Analytics**: Track which drafts perform best when published
